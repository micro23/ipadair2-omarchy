# J81 Omarchy A checkpoint — 2026-10-29

The target remains the full native Omarchy installation on the iPad's internal
storage. **That target is not complete.** There is no installed-root boot,
filesystem write/persistence qualification or untethered boot result.

## What is demonstrated

- The maintainer's refactored J81 hardware baseline boots and passes the
  [measured hardware checks](../../integration/2026-10-29/REPORT.md). Its
  integration and our packaging fix have reached upstream `main`.
- The actual Orchard Omarchy A v0.1.1 Quickshell UI, wallpaper/bar/menu/app grid,
  Foot, calculator and Firefox rendered natively through Labwc/simpleDRM at
  1536×2048. Keyboard injection executed as desktop UID 1000. The root was
  read-only NFS with a RAM overlay; those sessions were cleaned up. This was
  a full-root userspace demonstration, not a persistent installation.
- An Arch systemd unit-parser stage passed after a private `/dev/null` was
  supplied in its test namespace. No actual systemd PID 1 handoff was tested.
- The separate kernel `7.3.0-rc1-orchard-j81-storage-ro-v2mod` booted and exposed
  USB serial with ASP deferred. Manually loading the hardened ANS1 module
  exposed ten read-only namespaces. A guarded 4096-byte USERAREA read passed.
- This unit's USERAREA is **64,000,000,000 bytes**, with 4096-byte logical blocks.
  Primary GPT header/table CRCs and backup-header CRC passed. It contains one
  APFS partition at logical LBA 6..15,624,994 and no unallocated usable space.
  The later metadata check also read the backup entry array: both tables match
  and both entry CRCs pass. Raw blocks/identifiers stay private.

## Current blockers and limits

- Both source-built Pongo variants in the [fresh paired test](../pongo/COMPARISON.md)
  failed to enumerate and the owner observed iPadOS return. The known-working
  prebuilt remains the loader control. Quiet mode is not the sole demonstrated
  explanation; the underlying source-build failure remains unresolved.
- A separate `7.3.0-rc1-orchard-j81-storage-rwgated-v1` image compiles and
  assembles. Its source defaults to read-only and requires an explicit bounded
  USERAREA write range. That separate whole-kernel candidate did not reach a
  live write test. A boot with the proven
  prebuilt reached owner-visible Linux text, but no USB endpoint appeared even
  after reconnect. No storage-module write probe was sent in that session.
- A matching range-gated ASP module was built for the exact known-working
  `ro-v2mod` kernel ABI. Replacing only that module restored a live USB shell.
  The approved **one 4096-byte USERAREA write/read-back/restore passed**, at
  logical LBA 15,624,738, with the original bytes restored and verified.
  The immutable write window covers only that block; all nine auxiliary
  namespaces remain read-only. [Scoped result](../../experimental/j81-storage/reports/approved-block-test-result.json).
- Six native ARM64 tools from the pinned original v0.1.1 release execute on
  J81 over USB. Ext4 creation and all five e2fsck passes succeeded on a 64 MB
  **RAM file**; temporary mounts/files were cleaned. The original APFS layout
  was inspected read-only. This qualifies the tool runtime, not an installed root.
  [Device preflight](../../experimental/j81-storage/reports/native-tools-device-preflight.json).
- The candidate [internal-root policy](../../experimental/j81-storage/root-policy.json)
  masks J71b-specific units, pins the intended ext4 UUID/kernel and checks its
  write range and auxiliary read-only guards. It has not been applied to the
  original rootfs or iPad, parsed by the live Arch unit parser, or boot-tested.
- Native touch, charging policy, hardware audio, Bluetooth, GPU acceleration,
  suspend and long-duration reliability remain unqualified. Earlier PipeWire/
  WirePlumber clients do not establish physical audio output.
- A persistent root and untethered power-on boot are distinct. The working
  Pongo/m1n1 path still needs a host on each cold boot.

## Next engineering work

Preserve the proven loader and working kernel/module combination. Complete the
native-root bootstrap and exact installation plan, including verification of
cold-boot dependencies before destroying the only APFS partition. The newly
reviewed [A9 port](../../experimental/j81-storage/REFERENCE-OMARCHY-IPAD5.md)
provides useful internal-root, write-fence and systemd-handoff architecture,
but targets different silicon and retains iPadOS for its own cold-boot workflow.
Our dedicated-device preference does not establish an APFS-independent boot path.
The existing APFS layout cannot be treated as free Linux space. A one-block
test does not approve an erase, constitute an installer or prove long-term
storage reliability. The draft handoff has shell syntax validation only; no
actual systemd PID 1 handoff or internal-root persistence has been demonstrated.

This source update contains no Wi-Fi credentials, device ECIDs, unique partition
GUIDs, raw NAND blocks, Apple firmware or credential-bearing RAM images. Public
geometry and source hashes describe the experiment without exposing those data.


## Later installation preparation

Read-only APFS checkpoint/space-manager checks report 10.74 GB allocated and
53.26 GB free inside the original container. A proposal retains 16 GiB for the
established Apple boot workflow and allocates 46.82 GB to native Linux p2.
Apple's accepted resize minimum remains unverified; this is not an executed or
approved partition layout.

Adapted, attributed Apple-side tools compile for iOS 15 arm64 and verify their
signatures. Eight host sparse-file GPT tests pass. The deferred-ASP installer
bootstrap assembles with the exact qualified kernel/DTB/loader/bootargs, native
tools and a guarded systemd handoff. It has not been boot-tested. The root policy
now also pins `ROOT_DEVICE`. These changes prepare the native installation;
no resize, GPT update, format, installed-root boot or persistence result exists.
See [the proposal and sources](../../experimental/j81-storage/README.md).
